# ChatGPT 里的 Ash × Izzy 音乐卡片

这是一张可以直接显示在对话里的小卡片。它与现有手机网页/PWA 共用同一个 one-earbud 后端、网易云登录态、队列和播放心跳。

**默认仍是已经验收的 PWA 稳定模式。V2 新增手动选择的 ChatGPT 播放端。** 选“手机 PWA”时，声音来自手机；选“ChatGPT”时，声音来自这张卡片内的音频元素，手机 PWA 可以关闭。两端共用歌曲解析、队列和同一份播放状态，不自动抢占播放权。

## 怎么打开

1. 等 Render 上这次 main 更新显示 **Live**。服务仍是 Free，无新增环境变量，不需要更换两个口令。
2. 在 ChatGPT 的插件/应用详情页刷新工具信息，让它重新读取 app 专用工具和 `player-v2.6.html`。使用同一个 `/mcp` 地址与现有 OAuth，不需要更换口令。随后在新对话打开新卡片；旧卡片不会自动换脚本。
3. 刷新或彻底重开手机 PWA，让手机收到新增控件逻辑。首次使用先在 PWA 手动播一首。
4. 在新对话选择 **[Ash×Izzy] 分你一只耳机**，说“打开 Ash × Izzy 音乐卡片”或“用卡片显示我现在听的歌”。

AI 应调用 **`music_open_player`**。如果你说“放这首并打开播放器”，它应先调用原有 `music_play_now`，再调用 `music_open_player`。单纯后台读 `music_now_playing` 不会每次重建卡片，原有搜索、排下一首、加入队尾、完整歌词和分享工具继续可用。

已有 Neon 加密持久化继续保存网易云与 OAuth 状态；不需要重新扫码。免费实例重启仍会清空实时播放会话和临时音频地址，队列也可能随临时文件系统重置。不能把“当前没有播放心跳”等同于登录失效。

## V2：选择声音从哪里播放

卡片上方的“播放端”可以选 **手机 PWA / ChatGPT**，标题下方也会写明声音来源。

### 我的歌单与搜索（V2.6）

1. 打开新卡片，点 **我的歌单**，读取当前已登录网易云账号的创建、收藏歌单；**我喜欢的音乐**排在最前。使用原有账号和登录持久化，不新增登录或 secret。
2. 歌单显示封面、名称、歌曲数和来源。点进去查看歌曲，显示歌名、歌手及可用封面；每页 20 项，在卡片内滚动，点上一页/下一页翻页。**返回**从歌曲回到歌单；**播放器**随时回到播放控件。
3. 当前播放端选 **ChatGPT** 后点一首歌，卡片沿用当前播放会话加载音频并尝试播放，随后同步歌词、进度与服务端状态。首次或 iPhone 拒绝异步播放时，需再点中央播放按钮；准备好、指令已发送不等于已经出声。
4. 从聊天返回的新 UI 如果正在观察同一卡片原来的音频，会把选歌交给原实例执行，不启动第二个音频，也不重新 handoff。若当前 ChatGPT 播放权属于另一张独立卡片，先在播放器里明确接管，再选歌。
5. **手机 PWA**模式点歌沿用原队列/远程切歌通道，声音仍来自 PWA；未产生播放会话时仍需在手机点播放。浏览列表、搜索、翻页或返回本身不切歌、不换播放端。
6. 点 **搜索歌曲**，输入歌名或歌手后搜索，再点结果播放。文字按普通文本显示，不执行歌名或歌单中的 HTML。

沿用现有上游限制：最多读取 100 张歌单、每张前 500 首歌曲，搜索最多 20 首；列表元数据在服务内缓存约 60 秒，读失败可重试。点击只把所选歌曲放入共享队列，不替换或整份导入歌单；后续上下首继续使用现有队列与播放模式。歌曲版权、会员/试听和媒体加载限制照旧。

旧的“切聊天回来偶尔残留 PWA 提示”问题按用户要求暂停，进度见 [OPEN-ISSUES.md](OPEN-ISSUES.md)。V2.6 不继续调整该提示的 hydration 或播放恢复逻辑；待本功能实机验收后再恢复排查。

### 手机 PWA → ChatGPT

1. 刷新手机 PWA，至少播过一首；旧 PWA 脚本不会处理交接。iPhone 切到 ChatGPT 后可能挂起 PWA 的脚本，手机未必还能接收确认请求。
2. 在新卡片选择“ChatGPT”。优先等手机暂停并回报最终歌曲和进度；最多等待 12 秒。手机后台挂起、离线或旧脚本没有回报时，服务端收回旧端播放权、递增 epoch 并撤销旧会话，不再永久等待。继承切换时保留的歌曲和进度，**超时不会自动出声**。卡片约每 5 秒刷新，网络正常时在截止后的下一次刷新进入准备状态。
3. 看到“音频已准备好”后，点击卡片播放。首次或客户端手势限制时需要这一下；不会绕过 iPhone/ChatGPT 的自动播放限制，也不会在没出声时谎报播放成功。
4. 开始后可以关闭 PWA；卡片负责实际音频、暂停/恢复、上下首、可拖动进度与歌词。以后切歌继续读取同一队列的顺序/单曲循环/随机模式。

### ChatGPT → 手机 PWA

1. 打开已更新的手机 PWA。
2. 在卡片选择“手机 PWA”。卡片先停声，再把当前歌曲、进度和此前的播放意图交给手机。
3. 原手机已有有效播放会话时会尝试接着放；新开的手机页面只准备歌曲，需在手机点播放。Safari 仍可能要求手势。

### 等待、关闭与失败

V2.4 将“同一卡片恢复”和“换播放端”分开。首次在新的 v2.4 卡片播放后，宿主保存稳定的 `sourceId`；每次挂载另生成 `instanceId`，不把临时会话凭据存入快照。切换聊天再回来时自动调用 app 专用 `resume`，不发送 `switch`、不递增播放端 epoch：

- 原挂载仍持有音频：新 UI 直接读取同一份歌曲、进度和歌词，显示“此卡片播放”，通过既有控制工具遥控原音频，不另建一份声音。即使原挂载处于暂停也不擅自取代它。
- 原挂载已确认释放：在相同 mode、sourceId、streamId、epoch 下取得新的短期 lease，准备最新歌曲及释放位置；沿用服务端记录的播放意图，尝试续播。Safari 拒绝时提示点播放，不伪造成功。用户明确暂停优先于旧快照。
- 旧实例迟到的 report/release/resume 被退休实例及新 lease 隔离；同一快照同时恢复两个 UI，最多一个实例取得音频，其余仅观察，不互相 handoff。真正的 PWA ↔ ChatGPT 切换或另一张独立卡片明确接管，仍走原两阶段 handoff。

如果旧 iframe 被系统直接杀掉且没有释放确认，不能仅凭“当前没看见它”证明它已停声：恢复 UI 会继续观察同一会话，不自动创建第二份音频。宿主不提供 widgetState 时，也不能可靠识别跨挂载的同一卡片；继续提供状态和遥控，不根据同一首歌曲或公开 owner ID 冒充旧卡片。旧 v2.3 卡片没有保存身份，需按上方步骤打开新 v2.4 卡片完成一次首播后再验收恢复。

- 正常在线优先停声确认；12 秒没有确认则收回旧会话，保留歌曲、进度和此前播放意图，准备为暂停，等你点播放。等待期间也可以改回原播放端取消交接。保留的快照即使超过心跳时限也仍显示为“交接准备”，不会冒充手机实况或把进度清成 0。
- **系统限制：撤销播放权不能远程关闭已被 iOS 挂起的音频元素。** 超时提示出现后，若仍听到旧 PWA 的声音，先暂停它再点卡片播放。PWA 恢复脚本并收到同步结果或状态拒绝后会停声；旧会话、旧 epoch、迟到 heartbeat/ACK 都不能覆盖新端。不能保证在系统完全挂起期间物理停声，因此超时始终禁止自动播放。
- V2.2 不再仅因滚动离屏、IntersectionObserver 或 document.hidden 主动暂停音频；只要宿主仍运行卡片与桥接，播放中的心跳和工具轮询继续。关闭/销毁时仍停声并尽力发送释放请求，不绕过宿主 teardown。bfcache 的临时 pagehide 保存进度，pageshow 后校验服务端播放权。
- 如果宿主实际暂停了音频，状态会如实上报 paused，同时保留播放意图。回到卡片后先从服务端确认仍持有播放权，再尝试从原位置恢复；在卡片按暂停不会自动恢复。iOS 拒绝恢复时仍需点播放，不循环尝试或绕过手势限制。
- V2.3 的文字、按钮图标、无障碍标签与点击动作共用一份播放状态判定：当前卡片持有有效音频时读真实 `audio.paused/ended`；其余情况读服务端新鲜状态。`playbackIntent` 与保存的 `actualPlaying` 快照不作为正在播放的证明。聊天返回、visibility/focus/pageshow、宿主 globals 与重新可见时先同步重绘，再异步刷新。新 UI 实例看到另一个仍在播放的卡片时也显示暂停图标；点暂停沿用现有 `music_player_control` 通道，不隐式申请新播放权或执行 handoff。明确播放/接管仍走原有用户操作流程。
- V2.5 将底部提示也纳入同一次状态渲染：初始化只显示中性的连接提示，恢复后按服务端当前播放端和同一份实际播放判定显示文案。ChatGPT 正在播放时不再残留 PWA 首次播放提示；短期操作反馈限定在当前 stream/epoch/mode，准备播放、自动播放限制及媒体错误提示在成功播放后移除。真正的停声超时、连接错误仍保留相应提示，不修改播放权、音频或 PWA 流程。
- 支持时使用官方 `window.openai.setWidgetState` / `widgetState` 保存当前 songId、进度及播放意图（约每 5 秒，另在播放/暂停/seek/visibility/销毁时保存）。V2.4 另外保存 `playbackClient.sourceId`，它只标识同一张卡片，不是登录凭据。只存 UI 元数据，不存登录态、口令、sessionId 或音频能力 URL。歌曲快照标为“上次播放位置 · 非实况”，不能代替服务端实际状态。未提供该扩展的宿主继续依赖原有服务端状态与释放请求，不新增 localStorage 音乐状态源。
- 如果客户端直接杀掉页面，释放请求可能无法送达。新卡片仍可手动选择 ChatGPT，等待确认或上述超时准备，不会无限卡住；新页面打开本身不代表旧端已停声。服务重启后临时会话会重置，但登录持久化不受影响。
- ChatGPT 客户端是否允许 iframe 媒体、是否保留离屏页面及后台运行由平台决定；不保证系统挂起、卸载、锁屏或关闭对话后续播。
- 音频错误、版权限制、短试听、过期地址、网络或媒体 CSP 拒绝会显示提示；可重试或选回 PWA。不会退出网易云、重置 OAuth，或改写已有口令。
- 音频播放期间仍持续同步播放权和短期指令，避免 5 分钟无操作后遗漏 AI 的切歌指令。20 秒未收到成功的状态确认会暂停本卡片音频；恢复连接后需确认播放端并点击继续。

## 第一版有什么

- 专辑封面、歌名、歌手；封面不可用时显示唱片占位图。
- 手机回报的播放/暂停状态、进度和时长，当前歌词与前后各一句、当前行翻译。
- 播放/暂停、上一首/下一首、手动刷新和自动刷新开关。
- 手机优先的紧凑布局，44px 以上按钮，浅色/深色主题、键盘标签和屏幕阅读器提示。
- **不虚报播放成功**：按下按钮只显示指令已发送，图标和状态等手机的新心跳再改变。

“上一首”按当前队列的前一项选择，首尾循环；随机模式也不新增播放历史。“下一首”沿用 PWA 的选歌和播放模式。暂停时前后切歌只准备目标歌曲；PWA 没有产生过实际播放会话时，卡片的播放按钮不会替手机绕过首次手势限制。已有播放会话的恢复仍由 Safari/系统决定，拒绝时请在 PWA 点播放。

## 刷新与平台限制

PWA 遥控卡片可见时约每 5 秒通过宿主桥接读取一次状态，后台/不可见时停止，5 分钟无交互后关闭自动刷新。ChatGPT 音频仍在播放时，即使离屏或 hidden，也继续约每 5 秒校验状态、每 10 秒上报实际音频，避免我们自己的可见性判断触发同步超时。点“刷新”可重新开始。没有直接从 iframe 轮询私密 Web API，也不把 Web/MCP token 或网易云 cookie 放进卡片。

按 [官方 UI 文档](https://developers.openai.com/plugins/build/chatgpt-ui) 与 [运行时参考](https://developers.openai.com/plugins/reference)，组件运行于宿主 iframe；官方 widgetState 用于渲染间 UI 快照，不能作为业务状态权威或持久数据库。截至本次修复查阅的文档，没有找到保证 iOS 离屏 iframe 持续音频、后台音频服务或阻止宿主挂起/卸载的 API，不能把本次暂停全部归因于宿主：已确认我们原先的 visibilitychange 主动 pause 与 hidden 停止轮询也会导致问题。

官方另有 [PiP 展示模式](https://developers.openai.com/plugins/concepts/ui-guidelines)，可通过 `window.openai.requestDisplayMode({mode:'pip'})` 请求让 UI 在会话中保持可见；移动端可能改为全屏。这是展示能力，不是后台音频保证。本次保持 inline 小卡片，未擅自启用浮窗、Wake Lock、静音循环、后台脚本或其他保活绕过方式。需要可靠后台播放时仍选已稳定的手机 PWA。

显示的是**采样状态**，不是逐帧音频可视化。卡片 15 秒没有成功更新就停止宣称当前歌曲/歌词并禁用控件；服务器仍沿用原有 60 秒心跳和暂停 10 分钟的规则。手机同步间隔约 2 秒；手机后台被系统挂起、锁屏、断网或 Render 冷启动会延迟。控件指令只存内存，15 秒过期，旧歌的控件指令不会控制手机上的新歌。

ChatGPT 决定是否渲染 UI、是否允许按钮调用工具、是否要求确认。不同客户端/版本可能仅显示文字结果；没有桥接能力时卡片会提示降级，继续使用 PWA。V2 使用标准音频元素，不要求麦克风，不嵌套外部网页。只有 ChatGPT 播放端支持本卡片拖动进度；不承诺后台常驻播放。PWA 模式的原有规则保持不变。

## 接入方式与安全

按照当前 [OpenAI UI 文档](https://developers.openai.com/plugins/build/chatgpt-ui) 和 [quickstart](https://developers.openai.com/plugins/build/app-quickstart) 使用 MCP Apps：

- `music_open_player` 关联 `_meta.ui.resourceUri = ui://one-earbud/player-v2.6.html`，资源 MIME 为 `text/html;profile=mcp-app`。同时提供 ChatGPT 的 `openai/outputTemplate` 兼容别名。旧 `player-v2.html`、`player-v2.1.html`、`player-v2.2.html`、`player-v2.3.html`、`player-v2.4.html`、`player-v2.5.html` 地址仍可读取修复后的模板。
- 旧 `player-v1.html` 资源仍保留原 PWA 遥控脚本，避免已有连接缓存旧工具描述时找不到资源；它不获得 V2 音频能力。要使用 V2，刷新工具信息并打开新卡片。
- 组件用标准 `ui/initialize`、`ui/notifications/tool-result`、`tools/call`、尺寸变更通知和 `ui/resource-teardown` 桥接；以 `window.parent` 校验消息来源。初始化声明只支持 inline；通过 ResizeObserver 上报卡片尺寸。优先标准桥接，旧宿主有 `window.openai.callTool` 时可降级兼容。
- `music_player_state` 为只读、仅供 app 的刷新工具；视图适配层调用原有 `music_now_playing` 业务处理器、authority/queue 和缓存歌词，不重写网易云接口或 freshness 规则。
- `music_player_library` 为只读、仅供 app 的账号歌单/歌单歌曲/搜索适配器，调用 `authority.playlists/sourceSongs/search`，UID 继续由现有 authority 从已保存 profile 或 account 接口获取。白名单输出列表元数据，不向组件提供 UID、Cookie 或账号资料，不请求新的 OAuth scope。
- 用户点歌使用原 app 专用 `music_widget_playback` 的增量 `pick` 动作。服务端检查 stream/epoch/owner/instance、幂等 requestId 和异步读取前后的播放权；调用原 `authority.song`、`queue.playNow({by:'you'})`，沿用同一音频 descriptor/lease 或既有远程指令。旧歌曲报告仍拒绝写入，但明确标记 `staleTrack`，避免将迟到的旧歌报告误判为整个会话失去播放权。不变更 handoff、OAuth、Neon 或 PWA 内核。
- `music_player_control` 仅供 app，接受四种操作、当前歌曲预期值和必填 requestId。它复用现有 `/api/music/playback-sync` 通道；PWA 调用原播放内核，按命令 ID 去重。服务端保留最近 100 个控件请求；同一次重试必须复用 requestId，重启或淘汰后不保证服务端去重。
- `app` visibility 是宿主展示提示，不替代鉴权。读取 UI 资源和调用控件仍全部走原有 `/mcp` OAuth/Bearer 校验，原 `/api/music` 继续只接受网页口令。
- 新增仅供 app 的 `music_widget_playback`，处理模式选择、停声确认、受会话/序号/trackId 约束的状态上报、释放和队列切歌。写操作有请求 ID 去重；音频会话和媒体地址只在工具 `_meta` 中交给组件，不放进模型可见的歌曲结果。
- `now-playing.js` 仍是唯一播放状态模型。默认 PWA 保留 V1 会话及序号规则；切换额外使用 epoch、streamId、两阶段确认和 12 秒截止时间。每次读取/校验/写入都处理到期交接，不依赖旧端或进程定时器。`playback.handoff` 返回 `deadlineAt` 和准备快照，`playback.resume.reason` 区分 `acknowledged` / `timeout`；超时保存 `requestedPlaying` 而 `playing=false`。旧端/旧歌曲的报告、ACK 和晚到的旧 claim 不能重夺播放权。PWA 停声 ACK 采用更高序号，可越过迟到 heartbeat；失败重试保留停声前的最终快照。`music_now_playing` 的原工具名和已有字段保持兼容，实况过期仍返回 listening=false。
- CSP `connectDomains` 仍为空；资源域只增加现有 MCP 公网 origin（优先现有 `RENDER_EXTERNAL_URL`），封面仍限定 `p1`–`p10.music.126.net`。音频经 `/widget-media/临时能力地址` 流式转发，支持 Range；只允许服务端解析出的网易云 HTTPS 媒体域、验证每次重定向，不向上游传 Cookie/Authorization，不转发 Set-Cookie。能力地址仅用于当前 owner/track，10 分钟过期，换端/释放立即撤销后续访问。它不授予搜索、登录或普通 API 权限。
- 所有歌名、歌手和歌词用文本节点显示；封面与音频 URL 均校验，不执行歌曲内容中的 HTML。音频不落盘、不缓存整首；转发使用现有 Render Free 服务，仍受冷启动和网络限制。

HTML/CSS/JS 都在 `server/ui/player.html`，无需 CDN、前端构建、额外服务或付费资源。修改不兼容的组件时更新资源 URI，避免宿主缓存旧模板。外部 PWA、OAuth、音乐工具保持同一服务。
